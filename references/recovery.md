# 故障恢复：保留已完成工作

| 现象 | 先检查 | 下一步 |
|---|---|---|
| PowerShell 拒绝脚本执行 | 文件是否被下载标记、组织策略是否限制 | 用户按其设备政策允许运行可信脚本；不要修改全局执行策略或关闭保护 |
| conda 未找到 | bootstrap 的常见目录发现和 -CondaExe | 缺少则打开官方许可页，用户接受后自动安装 |
| 默认仓库条款提示 | 命令是否使用本包的 --override-channels -c conda-forge | 依赖仅从规定仓库取得；仍需接受某服务条款时交给用户，不自动 tos accept |
| 下载失败/代理问题 | TLS、磁盘空间、官方域名可达性、用户已有代理配置 | 修复网络后重跑；不关闭证书验证，不把代理密码写日志 |
| 安装包哈希不同 | 固定文件名与官方 SHA-256 是否一致 | 不执行；核对官方索引再更新 manifest，不改用未验证的 latest |
| conda 环境残缺 | conda-meta/history 与 Python 是否存在 | 保留目录；受识别环境用 -Repair，其他情况选择新 RUNTIME |
| Windows 中文/长路径异常 | 安装器或包具体错误、目录可写性 | 让用户指定短且可写的运行目录，再在后续命令一致使用 |
| Python 指向商店或 base | 是否通过 run.ps1/run.sh | 使用运行包装脚本，禁止拿 base 补包掩盖环境失败 |
| Key 缺失 | doctor 的 credential_present | 引导本地填写 .env；继续分镜、已有素材整理 |
| 401/403 | Key 所属地域、授权、额度、工作空间 | 用户在百炼控制台处理；不盲目重新生图 |
| 模型不存在或字段错误 | 模型是否在账号可用、接口形状是否正确 | 读该模型官方文档，修改配置或适配器并测试后再调用 |
| 已有 pending 标记 | 控制台请求是否成功、输出是否存在 | 先确认收费与结果，再决定人工恢复；不能直接删除后重试 |
| 浏览器安装但不可控 | Agent 是否有浏览器扩展/MCP、是否批准连接 | 开官方连接页面交给用户；未连接期间用其他获准路线或提示词包 |
| ChatGPT 登录/验证码/额度阻塞 | 当前真实页面 | 打开并保留页面，说明用户动作，暂停该步骤；不代付或绕过验证 |
| 图片中文/图示错误 | 逐字和物理关系验收 | 定位问题做有限修订，或换用户认可的素材方式 |
| ASR 不一致/无词时间戳 | 实际录音、响应格式、音频哈希 | 听音修正或更换可返回时间戳的识别方式；不生成假精确字幕 |
| 剪映草稿 schema 不匹配 | 实际版本、根与嵌套 timeline、备份 | 停文件写入，使用界面导入包或单独验证新适配 |
| 没有剪映/桌面控制 | 用户目标是否必须原生草稿 | 继续导入素材与字幕交付，并说明需要用户完成的软件操作 |

付费 POST 请求不自动重试；网络不确定时即使没有收到结果也可能已收费。GET 下载和环境依赖下载可以做有限次数重试，但不能掩盖哈希、权限或条款问题。

这个技能的“继续开工”是完成不依赖阻塞条件的工作、准确记录待办，再从保存状态恢复；不是伪造成功或绕过用户授权。
